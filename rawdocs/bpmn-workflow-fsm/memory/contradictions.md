# Contradictions and Tensions

## Open contradictions

- BPMN is highly business-readable but may introduce heavier governance and broader change surfaces for runtime adjustments.
- FSM/code-first approaches improve deterministic execution control but can reduce immediate readability for non-engineering stakeholders.
- Diagram-first teams expect visual sources of truth, while code-first teams prefer executable logic as source of truth.

## Resolved contradictions

- Resolved framing: BPMN and FSM are not strict competitors; BPMN can remain the communication/governance layer while FSM/code-first models run production behavior.
